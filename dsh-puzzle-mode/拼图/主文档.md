## 工作流
### 建项目并填真实文档
1. puzzle_mode op:list 看工作区已有项目，避免重复建
2. 读 package.json 的 name 与目录分层，定项目名
3. op:init 显式给 project 与 modules，一次建齐主文档与模块
4. 返回 rebound:false 时补一次 op:bind 把本会话绑上
5. op:source 记源码根，复查 fileCount 不为 0
6. 打开文件核行号，写模块索引与源码索引，每条带（源码: 文件:行）
7. op:read 复查各节条数，遇超限报错就改短重写

### 本地自检与交付
1. 跑 npm test，串完 5 份测试与跨插件互校
2. 跑 node --check lib/*.js，确认没有解析错误
3. 改过源码后单跑 node test/40-pre-execute.test.mjs 查拦截回归
4. 结果不符预期时先看 test 输出里的断言名，再改代码
5. 复跑 npm test 确认全绿，才报结论

### 审查与复测
1. op:audit 出 fixPlan 与真实五维，先把清单给用户看
2. 读源码补 vulnerability / redundancy，用 additions 回传
3. 用户点选要改的条之后，才动源码
4. 改完带 previousKeys 重跑 op:audit 复测
5. recheck.remaining 里还剩的条，如实说没消失

### 上游同步与互校
1. npm run sync:upstream 拉上游改动进本仓
2. npm run verify:cross 跑两侧互校脚本
3. npm run log:compat 归档互校结果
4. 段序或分工规则冲突时改 compat.json 的 textProbes

### 迁移与发版
1. op:rebuild 先 dry-run，逐文件看预览
2. 先备份工作区，本项目不自动备份
3. op:rebuild 带 apply:true 落盘
4. 用 append:false 逐节重写超长或无出处条目
5. 再跑 op:audit 确认条目级发现清零
6. tools/release.sh 发版并补齐 .github/release-*.md
